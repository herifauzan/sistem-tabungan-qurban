## 2024-05-24 - N+1 Read Bottleneck with Sheets Helper Functions
**Learning:** Using helper functions like `findRowIndexById` alongside direct `getRows` calls in the Google Sheets integration creates redundant API requests. Because each function call fetches the entire sheet, mixing these results in an N+1 read pattern. Also, when aggregating data after a write operation (e.g., updating a transaction status), you must ensure the in-memory array reflects this update before recalculating totals, otherwise you calculate based on stale data.
**Action:** Always fetch rows once per request (e.g., `getRows('SheetName')`) and compute necessary indices (`findIndex() + 2`) or aggregations in-memory. After making logic-affecting state changes (like marking a transaction 'Approved'), update the in-memory record directly prior to iterating over the dataset to avoid stale reads, rather than making another round-trip read to the API.
