## 2024-05-30 - [Optimize N+1 Reads in Google Sheets Integration]
**Learning:** Using `findRowIndexById` followed by `getRows` caused redundant API calls to Google Sheets, creating a significant bottleneck during transaction updates. Because Google Sheets acts as a pseudo-database via HTTP, every read operation incurs latency and risks hitting rate limits. Furthermore, recalculating totals using a fresh fetch required the data to be fully synchronized, risking stale reads or double-counting logic (e.g., adding `approvedAmount` to a fresh aggregate).
**Action:** Always fetch the target sheet's rows exactly once per request. Calculate necessary indices (`findIndex() + 2`) in-memory. Mutate the in-memory array to reflect the current update before performing aggregations to avoid stale read issues. Avoid using `findRowIndexById` if the row data itself is also needed.
