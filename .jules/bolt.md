## 2024-07-23 - Avoid redundant Google Sheets API reads by maintaining in-memory state
**Learning:** The application was experiencing significant performance bottlenecks in the transaction approval process. The root cause was redundant Google Sheets API reads (fetching the same sheet multiple times within a single request, compounded by using helper functions like `findRowIndexById` which also fetch the sheet). Furthermore, there was a risk of stale reads or double-counting when aggregating totals after a state change, because the subsequent reads might not yet reflect the write that just happened due to eventual consistency, or conversely, manually adding an amount to a freshly read total that *already* included the write.
**Action:** When performing updates and subsequent aggregations, fetch the rows exactly once at the beginning of the request. Manually compute indices (`findIndex() + 2`) from the in-memory array instead of calling helpers that trigger new API requests. Crucially, update the in-memory array with the new state *before* performing any aggregations to ensure accurate calculations and avoid needing to fetch the data again. This turns O(n) API calls into O(1) API calls per request for the same sheet.
